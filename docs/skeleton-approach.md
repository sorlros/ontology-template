# 골격 기반 스토리 생성 — 개념과 기존 방식과의 비교

작성일 2026-11-10. 턴 방식 AI 소설 서비스에서 일관성을 지키면서 LLM 비용을 줄이는 구조를 정리한 문서다.
금액은 모두 가정에 기반한 추정이고, 가정은 [8장](#8-비용-계산의-가정)에 모았다.

관련 문서: 엔진과 검증 기능의 사용법은 [`story-prototype.md`](story-prototype.md), 기존 서비스(NovelAIne)에 옮기는 계획은 [`novelaine-port-plan.md`](novelaine-port-plan.md).

---

## 1. 풀려는 문제

AI 가 유저의 입력을 받아 소설을 이어 쓰는 서비스에는 두 가지 문제가 함께 있다.

1. **일관성**: 이야기가 길어지면 모델이 앞의 내용을 다 볼 수 없다. 죽은 인물이 다시 나오고, 바뀐 관계가 원래대로 돌아가고, 준 물건을 다시 갖고 있다.
2. **비용**: 일관성을 지키려고 지난 이야기를 매번 모델에 넣으면, 이야기가 길어질수록 입력이 커진다.

두 문제는 같은 원인에서 나온다. **이야기의 사실을 모델의 입력(글)에만 담아 두기 때문**이다. 글은 길고, 모델은 그 안에서 사실을 매번 다시 찾아야 하며, 놓치면 모순이 생긴다.

## 2. 세 가지 방식

### 2.1 기록 주입 방식 (기존)

유저가 입력할 때마다 지난 장면의 원문이나 요약을 모델에 넣고 다음 장면을 쓰게 한다.

```
유저 입력 ─┐
지난 장면들 ─┼─▶ LLM ─▶ 다음 장면
캐릭터 설정 ─┘
```

- 사실의 정본이 글이다. 모델이 글을 읽고 스스로 기억해야 한다.
- 넣는 양을 늘리면 비용이 오르고, 줄이면 모순이 는다.
- 분석한 서비스(NovelAIne, 커밋 `d769011`)는 이 방식의 극단에 있다. 스트리밍 경로에서 지난 장면을 전혀 넣지 않고, 유저 입력도 영어 키워드로 압축해서 넣는다. 싸지만 직전 장면과의 연결이 보장되지 않는다.

### 2.2 상태 관리 방식 (실시간 즉흥 + 코드가 관리하는 상태)

이야기의 사실(생사, 위치, 소지품, 관계)을 코드가 관리하는 **세계 상태**로 따로 둔다. 상태는 **사건**으로만 바뀐다.

```
유저 입력 ─────────┐
세계 상태(코드) ───┼─▶ LLM ─▶ 다음 장면 + 사건 ─▶ 코드가 검사 ─▶ 상태 갱신
직전 장면·요약 ────┘                                  │
                                                      └─ 어긋나면 다시 쓰게 함
```

- 사실의 정본이 코드의 상태다. 모델은 제안하고 코드가 결정한다.
- "죽은 인물은 행동할 수 없다" 같은 규칙을 코드가 검사하므로, 모델이 잊어도 막을 수 있다.
- 이야기가 어디로 갈지는 여전히 매 턴 즉흥으로 정해진다. 문체를 잇기 위한 직전 장면과 줄거리 요약은 계속 넣어야 한다.

### 2.3 골격 기반 방식

이야기의 뼈대를 **장면 카드**의 연속으로 미리 만들어 둔다. 카드에는 그 장면에서 반드시 일어나는 사건이 적혀 있다. 유저와의 상호작용은 카드 안의 세부를 바꾸거나 카드의 사건을 바꾸는 형태로 들어온다.

```
[골격 작성 — 작품당 한 번]
  LLM(상위 모델) ─▶ 장면 카드들 ─▶ 코드가 전체 검증

[읽기 — 장면에 처음 도달할 때]
  장면 카드 + 그 시점의 상태 ─▶ 코드가 지시서 조립 ─▶ LLM(저가 모델) ─▶ 본문 ─▶ 저장

[유저가 바꿀 때]
  유저의 변경 ─▶ 코드가 뒤 장면을 판정 ─┬─ 유지        : 아무것도 하지 않음
                                        ├─ 다시 쓰기   : 본문만 다시 생성
                                        └─ 다시 계획   : 그 장면의 카드를 새로 작성
```

- 사실의 정본이 골격이다. 본문은 골격에서 만들어지는 결과물이고, 본문이 사실을 바꾸지 못한다.
- 일관성 검사가 실행 중이 아니라 **골격을 만들 때** 이뤄진다.
- 모델은 지난 이야기를 읽지 않는다. 그 장면에 필요한 사실만 담은 짧은 지시서를 받는다.

## 3. 골격 기반 방식의 구성 요소

### 3.1 세계 상태와 사건

상태는 네 가지다: 인물의 생사와 위치, 물건의 소지자, 인물 쌍의 관계.
사건은 다섯 종류이고 각각 전제 조건이 있다.

| 사건 | 전제 조건 |
|---|---|
| 행동(`act`) | 행동하는 인물이 살아 있다. 상대가 있으면 같은 장소에 있다 |
| 이동(`move`) | 인물이 살아 있고, 목적지가 정의된 장소다 |
| 사망(`die`) | 인물이 살아 있다. 되살리는 사건은 없다 |
| 전달(`give`) | 둘 다 살아 있고 같은 장소에 있으며, 주는 쪽이 그 물건을 갖고 있다 |
| 관계 변화(`relate`) | 둘 다 살아 있고, 정의된 관계 종류다 |

전제 조건에 어긋나는 사건은 적용되지 않는다. 이것이 "죽은 인물의 재등장"을 막는 장치다.

### 3.2 장면 카드

```yaml
- id: b09
  title: 대면
  fixed:                       # 반드시 일어나는 사건
    - {type: act, who: 카엘, with: 세라}
  uses: [은빛 단검]             # 이 장면이 쓰는 물건
  open: [대면의 결말]           # 유저가 바꿀 수 있는 부분
  pays: [단검의 내력]           # 회수하는 복선 (plants 는 심는 복선)
```

### 3.3 사전 검증

골격의 사건을 처음 상태에서 끝까지 순서대로 적용한다. 성립하지 않는 사건은 사유를 남기고 건너뛴 채 끝까지 가서, 문제를 한 번에 모두 찾는다.

- **오류**: 전제 조건 위반, 장면이 쓰는 물건을 그 장면의 인물이 갖고 있지 않음, 심지 않은 복선의 회수, 겹치는 장면 ID.
- **경고**: 끝까지 회수되지 않는 복선, 두 번 회수되는 복선, 어느 장면에도 나오지 않는 인물.

독자가 읽기 전에, LLM 을 부르지 않고 끝난다.

### 3.4 지시서

장면을 쓸 때 모델에 주는 입력이다. 코드가 그 장면에 들어서는 시점의 상태에서 **그 장면이 읽는 사실만** 골라 만든다.

```
장면: b09 대면
인물: 카엘(항구), 세라(항구)
물건: 은빛 단검 — 카엘
관계: 세라·카엘 적대
반드시: type=act who=카엘 with=세라
열린 부분: 대면의 결말
복선 회수: 단검의 내력
```

- 들어가는 것: 사건에 나오는 인물의 생사와 위치, 같은 장소에 있는 다른 인물, 그들 사이의 관계, 장면이 쓰는 물건의 소지자, 반드시 일어날 사건, 열린 부분, 복선.
- 크기가 이야기 길이와 무관하다. 10번째 장면이든 1,000번째 장면이든 같다.
- **지시서가 같으면 모델이 받는 입력이 같다.** 그래서 지시서를 키로 본문을 저장해 두고 다시 쓸 수 있다.

### 3.5 변경 영향 판정

유저가 한 장면의 사건을 바꾸면, 코드가 원래 골격과 바뀐 골격을 각각 끝까지 적용해 뒤 장면을 셋으로 나눈다. 코드 변경에서 영향받는 파일만 다시 빌드하는 것과 같은 원리다.

| 판정 | 조건 | 할 일 | LLM 호출 |
|---|---|---|---|
| 유지 | 지시서가 그대로다 | 없음 | 0 |
| 다시 쓰기 | 사건은 성립하지만 지시서가 달라졌다 | 본문만 다시 생성 | 장면당 1 (저가 모델) |
| 다시 계획 | 사건이 성립하지 않게 됐다 | 그 장면의 카드를 새로 작성 후 본문 생성 | 장면당 2 |

바꾼 장면 자체가 성립하지 않으면(죽은 인물을 행동시키는 변경) 사유와 함께 막는다.

샘플 골격(9장면)에서의 결과:

| 유저의 변경 | 유지 | 다시 쓰기 | 다시 계획 |
|---|---|---|---|
| 3장면에서 세라를 죽임 | 1 | 2 | 3 |
| 2장면에서 세라가 숲에 따라오지 않음 | 2 | 5 | 0 |
| 3장면에서 단검을 받지 않음 | 5 | 0 | 1 |
| 5장면에서 죽은 인물을 행동시킴 | 변경 자체를 막음 | | |

### 3.6 유저의 변경이 들어오는 세 단계

1. **세부 변경**(대사, 방식, 분위기): 사건에 영향이 없다. 그 장면의 본문만 다시 쓴다.
2. **장면 안의 분기**(설득할지 싸울지): 카드에 미리 정의된 결과 중 하나로 간다. 뒤 장면은 그대로다.
3. **골격을 건드리는 변경**(뒤에 필요한 인물을 죽임): 영향 판정으로 걸린 장면만 다시 쓰거나 다시 계획한다.

## 4. 방식별 비교

### 4.1 구조

| 항목 | 기록 주입 | 상태 관리 | 골격 기반 |
|---|---|---|---|
| 사실의 정본 | 지난 장면의 글 | 코드의 세계 상태 | 골격(장면 카드) |
| 이야기의 방향 | 매 턴 즉흥 | 매 턴 즉흥 | 미리 정해 둠 |
| 일관성 검사 | 없음(모델의 기억에 의존) | 생성 후 코드가 검사, 어긋나면 재생성 | 골격 작성 시 한 번, 이후는 변경분만 |
| 모순의 발견 시점 | 독자가 읽은 뒤 | 생성 직후 | 독자가 읽기 전 |
| 복선의 회수 | 최근 기록 밖이면 잊힘 | 따로 목록을 유지해야 함 | 골격에 계획되어 검증됨 |
| 유저의 자유도 | 무제한 | 무제한(규칙 위반만 거부) | 설계한 범위 안 |

### 4.2 LLM 호출

| 항목 | 기록 주입 | 상태 관리 | 골격 기반 |
|---|---|---|---|
| 호출 시점 | 유저 입력마다 | 유저 입력마다 | 골격 작성 때, 장면에 처음 도달할 때, 변경으로 걸린 장면에 |
| 입력 내용 | 지난 장면의 원문·요약 | 상태 + 직전 장면 + 요약 | 그 장면의 지시서 |
| 입력 크기 | 이야기 길이에 따라 증가(또는 잘라 냄) | 일정 | 일정, 가장 작음 |
| 호출 간 의존 | 앞 턴 결과가 있어야 함 | 앞 턴 결과가 있어야 함 | 장면끼리 독립(병렬·배치 가능) |
| 사건 추출 호출 | 없음 | 턴마다 필요(생성과 합치거나 별도) | 없음(사건이 골격에 있음) |
| 검증·영향 판정 | — | 코드 | 코드 |
| 모델 배정 | 한 모델 | 한 모델(+추출용 저가 모델) | 계획은 상위 모델, 집필은 저가 모델 |
| 결과 재사용 | 불가 | 불가 | 지시서가 같으면 본문 재사용 |

골격 기반에서 새로 생기는 호출:

- **유저 입력 해석**: 자유 문장을 "어느 장면의 어떤 사건을 바꾸는가"로 옮긴다. 저가 모델의 짧은 호출이고, 선택지 UI 로 받으면 필요 없다.
- **다시 계획**: 성립하지 않게 된 장면의 카드를 새로 짠다. 상위 모델이지만 출력이 카드 하나라 짧다.

### 4.3 턴(장면) 하나의 토큰

| 방식 | 입력 | 출력 |
|---|---|---|
| 기록 주입 — 분석한 서비스의 현재 구조(지난 장면 없음, 호출 3회) | 약 1,950 | 약 1,150 |
| 기록 주입 — 원문 8장면 | 약 9,000 | 약 1,250 |
| 기록 주입 — 전체 원문 누적 | 평균 약 600,000 | 약 1,250 |
| 상태 관리 — 직전 장면 전문 + 요약 + 상태 + 인물 메모 + 복선 | 약 3,400 | 약 1,250 |
| 골격 기반 — 장면 생성 | 약 1,100 | 약 1,000 |
| 골격 기반 — 유지 판정된 장면 | 0 | 0 |

## 5. 비용 비교

4MB(한글 약 170만 자, 본문 약 120만 토큰, 장면 1,200개) 분량의 소설 한 편 기준. 모델은 비교를 위해 Claude Sonnet 5.5($2 / $10, 100만 토큰당 입력 / 출력)로 맞췄다.

### 5.1 독자 한 명이 끝까지 읽는 비용

| 방식 | 비용 | 비고 |
|---|---|---|
| 기록 주입 — 현재 구조(지난 장면 없음) | 약 $18 | 가장 싸지만 연결이 보장되지 않는다 |
| 기록 주입 — 원문 8장면 | 약 $37 | |
| 기록 주입 — 전체 원문 누적 | 약 $1,450 | 캐시 없이 계산 |
| 상태 관리 | 약 $23 | |
| 골격 기반 — 변경 없이 읽기 | 약 $11 | 골격 $4 + 본문 $7. 다음 독자부터는 $0 |
| 골격 기반 — 변경 100회 | 약 $20 | 위 $11 + 변경 $9 |

비용의 대부분은 출력이다. 상태 관리 방식의 $23 중 $15 가 출력이다. 그래서 입력을 줄이는 것보다 **출력량이 많은 집필을 어느 모델에 맡기는가**와 **이미 쓴 본문을 다시 쓰지 않는가**가 비용을 더 크게 좌우한다.

### 5.2 골격 기반의 항목별 비용

작품당 한 번:

| 항목 | 모델 | 비용 |
|---|---|---|
| 골격 작성(장면 카드 1,200장) | Opus 5.5 | 약 $4 |
| 본문 전체 | Sonnet 5.5 배치 | 약 $7 |
| 본문 전체 | Haiku 5.5 배치 | 약 $0.4 |

변경이 있을 때:

| 항목 | 비용 |
|---|---|
| 변경의 영향 판정 | $0 (코드) |
| 장면 1개 다시 쓰기 | 약 $0.012 |
| 장면 1개 다시 계획 + 쓰기 | 약 $0.027 |

### 5.3 독자 수에 따른 총비용

독자 한 명이 변경으로 쓰는 비용을 $3 으로 가정했다.

| 독자 수 | 상태 관리(실시간) | 골격 기반 |
|---|---|---|
| 1명 | $23 | $14 |
| 100명 | $2,300 | $311 |
| 1,000명 | $23,000 | $3,011 |

실시간 방식은 독자마다 처음부터 새로 생성하므로 비용이 독자 수에 비례한다. 골격 기반은 본문을 공유하므로 독자가 늘어도 각자가 바꾼 부분만큼만 늘어난다.

## 6. 골격 기반 방식이 불리한 경우와 한계

**제품 측면**

- **유저의 자유도가 줄어든다.** 무엇이든 입력할 수 있다는 것이 실시간 즉흥의 매력이다. 골격이 단단할수록 선택지형 게임에 가까워진다. 어디까지 열어 둘지는 기술이 아니라 제품의 결정이다.
- **골격의 질이 전부를 결정한다.** 코드는 사실의 모순을 잡지만 이야기가 재미있는지는 판단하지 못한다.

**비용 측면**

- **독자가 한 명뿐인 작품**은 공유 이점이 없다. 본문을 미리 다 만들면 읽지 않은 부분의 비용이 낭비되므로, 장면에 처음 도달했을 때 생성해 저장하는 편이 낫다.
- **초반의 큰 변경**은 뒤 장면 대부분을 다시 계획하게 만든다. 이때 비용은 새 소설을 처음부터 만드는 것과 같다.
- **분기가 많아지면 재사용률이 떨어진다.** 독자마다 지시서가 달라지면 저장된 본문을 쓰지 못하고, 총비용이 실시간 방식에 가까워진다.

**품질 측면**

- **이전 장면의 문장을 이어받지 못한다.** 장면을 독립 호출로 만들려면 직전 장면의 원문을 입력에 넣지 않아야 한다. 넣으면 문체 연결은 좋아지지만 병렬 실행과 본문 재사용이 깨진다.
- **부분만 다시 쓰면 이음매가 생길 수 있다.** 앞뒤 장면과 문체나 호흡이 어긋날 수 있다.
- **저가 모델의 집필 품질**은 지시서가 충분히 구체적이라는 전제의 기대다.

**판정의 한계**

- 영향 판정은 "지시서에 없는 사실은 본문이 쓰지 않는다"는 가정 위에 있다. 모델이 지시서 밖의 인물이나 물건을 본문에 끌어오면, 유지로 판정된 장면에 낡은 내용이 남는다.
- 다시 계획이 필요한 장면을 찾아 주기만 한다. 새 카드를 짜는 것은 사람이나 모델의 일이다.
- 복선은 이름이 같은지만 본다.
- 상태가 다루는 것은 생사, 위치, 소지품, 관계 유형뿐이다. 누가 무엇을 아는지, 약속, 감정의 정도는 범위 밖이다.

## 7. 절충안

완전한 골격과 완전한 즉흥 사이에 중간이 있다.

| 층 | 내용 | 바뀌는 빈도 |
|---|---|---|
| 고정 뼈대 | 이야기 전체의 큰 전환점 10~20개 | 거의 바뀌지 않음 |
| 유동 계획 | 다음 5~10장면의 구체적인 카드 | 유저가 벗어나면 그 구간만 다시 계획 |
| 자유 영역 | 카드 안의 세부(대사, 방식) | 유저 입력대로 |

방향성과 짧은 지시서의 이점을 얻으면서 자유 입력을 유지한다. 유동 계획의 범위가 짧아서, 큰 변경이 있어도 다시 계획하는 장면 수가 제한된다.

## 8. 비용 계산의 가정

실측이 아니라 가정이다. 값이 바뀌면 결과가 비례해서 바뀐다.

| 가정 | 값 |
|---|---|
| 4MB 의 글자 수 | 약 170만 자 (한글 3바이트, 공백·문장부호 1바이트, 평균 2.44바이트) |
| 글자당 토큰 | 0.7 (모델마다 다르다. Haiku 5.5 는 같은 글을 약 30% 더 센다) |
| 장면당 본문 | 1,000토큰 → 장면 1,200개 |
| 골격 기반의 장면당 입력 | 1,100토큰 (공통 규칙·문체·인물 말투 800 + 지시서 300) |
| 장면 카드 | 150토큰. 골격 작성은 20장면씩 60회, 회당 입력 3,000토큰 |
| 변경 1회가 건드리는 장면 | 다시 쓰기 5개, 다시 계획 1개 (임의로 잡은 값) |
| 배치 처리 | 표준 요금의 절반 |
| 포함하지 않은 것 | 추론 토큰(출력 요금으로 청구된다), 유저가 마음에 들지 않아 다시 생성하는 턴, 환율 |

특히 "변경 1회가 건드리는 장면 수"는 근거가 약하다. 샘플 9장면에서는 변경 하나에 뒤 장면의 절반 이상이 걸렸다. 장면이 1,200개인 작품에서의 비율은 측정하지 않았다.

## 10. 측정해야 알 수 있는 것

이 문서의 결론은 아래 값에 달려 있고, 모두 아직 모른다.

1. **변경 하나가 평균 몇 장면을 건드리는가** — 실제 규모(수백 장면)의 골격에서.
2. **독자 간에 지시서가 얼마나 겹치는가** — 본문 재사용률을 결정한다.
3. **지시서만 받은 모델이 지시서 밖의 사실을 얼마나 끌어오는가** — 영향 판정의 전제.
4. **저가 모델이 지시서로 쓴 본문의 품질** — 상위 모델의 실시간 본문과 나란히 비교.
5. **직전 장면 원문 없이 이어 쓴 장면의 문체 연결** — 독립 호출의 대가.
6. **한국어 본문의 실제 토큰 수** — 모델별로.
